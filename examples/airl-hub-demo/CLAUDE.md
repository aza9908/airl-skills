# CLAUDE.md — демо-хаб AIRL

## Что это
Демо хаба руководителя для AIRL (AI Research Labs, Алматы): экран руководителя + сервисы отделов
«Финансы», «Продажи», «Обучение» на **синтетических** данных в форме выгрузок 1С, банков и amoCRM.
Цель — доказать, что методика VibeOps (навыки `skills/airl-*`) доводит до работающего хаба.
Владелец: команда AIRL (демо). Боевого сервера и доступа к настоящей 1С нет.

## Документы (читать по необходимости, не целиком)
- `COMPANY_MAP.md` — карта компании: показатели (раздел 4), отделы (6), роли (7), контракт входа (8), дизайн (9)

- `SECURITY.md`, `REVIEW.md`, `DEVOPS.md`, `HUB.md` · `METHODOLOGY_LOG.md`, `SKILL_GAPS.md` — отчёт о методике

## Стек и запуск
- Стек: PostgreSQL 16 (raw → core → metrics → mart_<отдел>), Node.js 22 без фреймворков (`pg`), PWA на чистом JS, Caddy
- Без Docker: `bash scripts/setup_db.sh` → `bash scripts/dev_up.sh` → http://127.0.0.1:8080/login · стоп: `bash scripts/dev_down.sh`
- Docker: `bash scripts/init_env.sh && docker compose up -d --build` → http://localhost:8080/login
- Тесты: `cd services && npm test && npm run lint` · всё вместе на стенде: `bash scripts/verify.sh`
- Ключи: в `.env` (в git не попадает), образец — `.env.example`; ключ подписи JWT — `.secrets/` (создаётся сам)

## Правила проекта
- Цифры только из `metrics` (формулы — раздел 4 карты); в сервисах и браузере ничего не пересчитываем.
- Сервис пишет только в свою витрину `mart_<id>` под своим пользователем `svc_<id>` — права в базе.
- Модули из `skills/airl-modules` копируются в `dwh/modules/` без правок; настройка — `dwh/marts/*_config.sql`.
- Вход только через хаб (JWT RS256, cookie `airl_session` или Bearer); роль — из проверенного токена.
- ПДн (имена и ИИН физлиц) маскируются на сервере; в `/api/hub/summary` — только агрегаты.
- Без `style="…"` и `onclick="…"` в разметке (CSP без 'unsafe-inline'); интерфейс на русском.
- Синтетика: телефоны +7 700 000 xx xx, БИН 9914…, ИИН 9913…; настоящих людей и компаний нет.
