# Телефония: звонки, записи, пропущенные

Справочник `/airl-integrations`. Типовые требования: видеть звонки клиента
в карточке, считать пропущенные и время перезвона, слушать записи для контроля
качества, создавать задачу на перезвон. В курс берётся, только если договор
с оператором уже есть (`scope.md`).

## Сначала — встроенная интеграция CRM

Если у клиента Bitrix24 или amoCRM, **первый выбор — готовая интеграция оператора
с CRM** (приложение из маркетплейса CRM или встроенная телефония): звонок сам
создаёт дело в карточке, лида по новому номеру, запись прикрепляется к звонку.
Это настройка (`/airl-connect`), а не разработка. Данные звонков потом забираются
из CRM (`crm.activity.list`, события amoCRM) в хранилище.

Свою интеграцию строим, только если CRM нет, CRM не поддерживает оператора, или
нужны данные, которых CRM не отдаёт (например, точное время ответа для SLA).

## Операторы

Виртуальные АТС и SIP-операторы в KZ и UZ — кандидаты, наличие API и вебхуков
**уточнить у поставщика** в день выбора:
- международные облачные АТС, работающие с номерами KZ/UZ (уточнить, выдают ли
  местные номера и где хранят записи);
- облачные АТС местных операторов связи (KZ: Beeline, Kazakhtelecom, Kcell и др.;
  UZ: Beeline, Ucell, Uztelecom и др.) — уточнить наличие API;
- IP-АТС на своём сервере (Asterisk/FreePBX) — события через AMI/ARI или CDR в базе.

Что спросить у поставщика: вебхуки событий звонка (какие, формат, подпись,
повторы); API истории звонков (для сверки и пропущенных вебхуков); доступ к записям
(ссылка, срок жизни, авторизация); где физически хранятся записи (страна); лимиты;
тестовый номер или песочница.

## События звонка

Типовой набор (имена у каждого оператора свои — проверить):

| Событие | Что приходит | Что делаем |
|---|---|---|
| начало (входящий/исходящий) | ID звонка, номера, линия, время | создаём звонок в `int_inbox` → `core.calls` |
| ответ | кто ответил (внутренний номер), время | время ответа для SLA |
| завершение | длительность, итог (отвечен, пропущен, занято) | итог, запуск правил пропущенных |
| запись готова | ссылка или ID записи | сохраняем ссылку/ID, не файл |

- Приём — по шаблону inbox: подпись или секрет (если оператор не подписывает —
  секретный путь + белый список IP оператора, записать как риск), `event_id`
  = ID звонка + тип события; ответ 200 сразу.
- События приходят не по порядку и повторяются: звонок собирается по ID звонка,
  итог — по последнему событию «завершение»; повтор ничего не меняет.
- Страховка: раз в час — история звонков за последние 2 часа по API, добор
  пропущенных вебхуков. Сверка за сутки: число звонков у оператора = у нас.

## Связь с клиентом

- Номер приводится к E.164 (`+7XXXXXXXXXX`, `+998XXXXXXXXX`) и ищется по ключам
  склейки из карты (раздел 3). Один номер у нескольких клиентов — не выбираем
  наугад: звонок без клиента + задача на разбор.
- Новый номер и нет CRM-лида — по правилу клиента: создать лида (через outbox
  в CRM, если запись в CRM разрешена исключением карты) или показать в списке
  «неизвестные номера».
- Сотрудник — по внутреннему номеру; таблица соответствия «внутренний номер →
  пользователь» ведётся у клиента, мы её только читаем.

## Пропущенные и перезвон

- Пропущенный = входящий без ответа (включая сброс в очереди и после рабочего
  времени — правило записать с клиентом).
- Несколько попыток с одного номера за окно (например, 30 минут) — один пропущенный,
  а не пять задач. Перезвонили (исходящий на этот номер или входящий отвеченный) —
  пропущенный закрыт, время перезвона считается.
- Задача на перезвон — в CRM (готовая интеграция) или в модуле обращений
  (`complaints`/`service-requests`); уведомление через `airl_notifications`
  с `dedup_key`.
- Показатели: доля пропущенных, медиана времени перезвона, не перезвонили за день —
  по определениям карты (раздел 4).

## Записи разговоров и персональные данные

- Запись разговора — персональные данные (голос, а в разговоре — что угодно,
  включая здоровье). По умолчанию **файлы остаются у оператора**; у нас — ID
  и ссылка, доступ к прослушиванию — по роли, просмотр пишется в журнал.
- Если записи нужно хранить у себя (срок у оператора короткий) — сервер в стране
  по профилю, срок хранения согласовать с юристом, удаление по сроку.
- Ссылки на записи часто временные и с токеном в адресе — не логировать, не
  показывать в интерфейсе как есть; отдавать через свой сервер по роли.
- Уведомление «разговор записывается» в начале звонка и основание обработки —
  **проверить у юриста** по закону страны; текст — у оператора в настройках АТС.
- Расшифровка и анализ звонков ИИ — только после решения юриста и с моделью,
  допустимой для этих данных (правило 10 карты); в курс не входит.

## Приёмка

- [ ] тестовый звонок: начало, ответ, конец, запись — всё в карточке за минуту;
- [ ] повтор вебхука не создаёт второй звонок; поддельный — 401/отклонён;
- [ ] пропущенный → одна задача на перезвон; перезвон закрывает её;
- [ ] сверка звонков за сутки с историей оператора сходится;
- [ ] записи слушаются только ролями из карты, просмотр в журнале.
