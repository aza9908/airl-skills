# 1С: чтение большими объёмами и запись обратно

Справочник `/airl-integrations`. Относится к типовым конфигурациям на платформе
8.3 (Бухгалтерия, УТ, КА, ERP, ЗУП, в том числе редакции для Казахстана
и Узбекистана). Версии платформы и конфигураций у клиентов разные: всё, что
зависит от версии, — «проверить на базе клиента».

## Три способа, по порядку предпочтения

| Способ | Чтение | Запись | Кто делает сторону 1С | Когда |
|---|---|---|---|---|
| Стандартный интерфейс OData | да | технически да, нами — нет | администратор 1С: публикация и состав интерфейса | чтение справочников и документов без программиста |
| HTTP-сервис в расширении | да | **да — основной путь** | программист 1С клиента (или франчайзи) | запись, инкремент по плану обмена, большие объёмы |
| Обмен файлами | да | да | программист 1С: регламентное задание | нет веб-публикации, закрытый контур |

**Прямой SQL в базу СУБД под 1С — никогда**: ни чтение, ни запись. Хранение
в СУБД — внутреннее дело платформы (имена таблиц вида `_Document123`, итоги
регистров, блокировки); запись в обход ломает итоги и проведение, чтение ломается
при каждом обновлении конфигурации. Допустимость по лицензии — проверить у 1С.

## Чтение: OData

- База публикуется на веб-сервере (Apache или IIS) из конфигуратора; адрес вида
  `https://<сервер>/<имя_публикации>/odata/standard.odata/` — проверить на публикации.
- Объекты включаются в состав стандартного интерфейса (в конфигураторе или
  обработкой «Настройка стандартного интерфейса OData» — проверить для версии).
  Только нужные объекты, не «всё».
- Имена сущностей по типу метаданных: `Catalog_Контрагенты`,
  `Document_РеализацияТоваровУслуг`, `AccumulationRegister_<имя>_RecordType`
  и т.п.; поддерживаются `$filter`, `$select`, `$top`, `$skip`, `$format=json` —
  проверить набор на версии платформы.
- Пользователь — отдельный технический, с ролью только на чтение нужных объектов.
  Сессии OData занимают лицензии клиента — **уточнить у администратора 1С**, хватит ли.
- Инкремент: у документов есть `Date`, но нет надёжной «даты изменения». Документ
  задним числом OData-фильтр по `Date` не поймает. Для больших объёмов и инкремента —
  HTTP-сервис на **плане обмена** (ниже), для справочников — полная выгрузка ключей
  раз в сутки + пометка удалённых.
- Большие таблицы — страницами `$top`/`$skip` по стабильной сортировке, ночью,
  с продолжением с места остановки; на каждую страницу таймаут и повтор.

## Чтение и запись: HTTP-сервис в расширении

Пишет **программист 1С клиента** по нашему контракту, в **расширении конфигурации**
(`.cfe`), чтобы типовая конфигурация осталась на поддержке и обновлялась.
Мы пишем контракт и тесты, он — код в 1С. Его часы и срок — в план на неделе 0.

Контракт (пример — согласовать с программистом):

| Метод | Что делает | Ответ |
|---|---|---|
| `GET /changes?node=airl&limit=500` | изменения из плана обмена с узла AIRL | пачка объектов + номер сообщения |
| `POST /changes/ack` | подтвердить приём пачки — 1С снимает регистрацию | `ok` |
| `PUT /payment-status/{external_id}` | статус оплаты заявки | ссылка, состояние |
| `PUT /orders/{external_id}` | заказ клиента (черновик) | ссылка, номер, состояние |
| `PUT /documents/{external_id}` | документ в статусе «черновик» на проверку бухгалтеру | ссылка, номер |
| `GET /objects/{external_id}` | найти объект по нашему ID (для сверки) | объект или 404 |

**Идемпотентность на стороне 1С.** Регистр сведений `ВнешниеИдентификаторы`
(источник, внешний ID → ссылка на объект). Метод сначала ищет по внешнему ID:
нашёл — обновляет этот объект или возвращает его как есть; не нашёл — создаёт
и пишет запись в регистр в той же транзакции. Повтор нашего запроса не создаёт дубль.
`external_id` = наш `idempotency_key` без версии (версия — в теле).

**Что пишем:**
- статус оплаты, согласования, отгрузки — в реквизиты или регистр сведений, не в
  проводки;
- заказы клиентов — **записанными, но не проведёнными**; проводит менеджер или учёт;
- первичные документы (поступления, реализации, заявки на расход) — **черновиками**
  (записан, не проведён, комментарий «создан AIRL, проверить»). Бухгалтер проверяет
  и проводит сам. Проводить из интеграции — только по письменному решению главного
  бухгалтера, записанному в карту (раздел 8, исключения).

**Номера** присваивает 1С. Мы номер не передаём; в ответе получаем номер и ссылку
и сохраняем в `external_id`/`response`.

**Закрытый период** (дата запрета изменения): метод возвращает понятный код,
например `PERIOD_CLOSED` (имя согласовать). Это неповторяемая ошибка: запись уходит
в dead, бухгалтер решает — открыть период или поменять дату.

**Коды ответов** (согласовать): 200/201 — успех; 409 — объект уже есть по ключу
с другим содержимым; 422 — ошибка данных (нет контрагента, номенклатуры); 423 —
объект заблокирован пользователем (повторяемая); 503 — база на обновлении
(повторяемая). В теле — код ошибки и текст без персональных данных.

**Блокировки и производительность:** один объект — одна транзакция; пачки по
50–100 объектов; не писать в часы закрытия месяца (согласовать окно с бухгалтерией).

**Доступ:** отдельный пользователь 1С с ролью только на HTTP-сервис расширения;
базовая аутентификация по HTTPS; пароль — секрет `INT_1C_*`. Публикация наружу —
только через HTTPS и, по возможности, белый список IP сервера хаба.

## Обмен файлами — запасной путь

Когда веб-публикации нет и не будет (закрытый контур, политика ИТ):
- мы кладём файлы JSON/XML в обменную папку (SFTP или сетевая папка), по файлу
  на пачку, имя с номером пачки;
- регламентное задание 1С забирает, загружает с той же логикой
  `ВнешниеИдентификаторы` и пишет файл-квитанцию с результатом по каждому объекту;
- мы читаем квитанции и отмечаем записи outbox; нет квитанции за N минут — оповещение.
Типовой формат обмена EnterpriseData (синхронизация данных в БСП) — вариант для
обмена между конфигурациями 1С; для нашего случая обычно проще свой формат —
решить с программистом.

## Кто что делает

| Работа | Кто |
|---|---|
| Контракт методов, коды ошибок, тестовые случаи | инженер AIRL |
| Расширение, HTTP-сервис, регистр внешних ID | программист 1С клиента |
| Публикация на веб-сервере, пользователь, лицензии | администратор 1С клиента |
| Тестовая копия базы для проверки | администратор 1С клиента |
| Решения про проведение и закрытые периоды | главный бухгалтер |

## Приёмка (на тестовой копии базы)

- [ ] повтор каждого метода с тем же `external_id` не создаёт второй объект;
- [ ] документ создаётся непроведённым, номер присваивает 1С;
- [ ] запись в закрытый период — `PERIOD_CLOSED`, не исключение платформы;
- [ ] нет контрагента/номенклатуры — 422 с понятным кодом;
- [ ] пачка 500 объектов проходит за согласованное время, пользователи 1С не ждут блокировок;
- [ ] `GET /objects/{external_id}` находит всё отправленное — на нём работает сверка;
- [ ] обновление типовой конфигурации на копии не ломает расширение;
- [ ] откат: созданное помечается на удаление (не удаляется) по списку external_id.
