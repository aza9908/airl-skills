# Чек-лист курса: что проверяет /airl-progress

Каждый пункт получает оценку от 0 до 1 (частичное выполнение — 0,3–0,75).
Пункт со знаком «—» не относится к участнику и не считается: например,
`airl.service.json` у участника со своим продуктом или «живой /healthz», если
адрес в списке не указан. Веса пунктов и этапов — в `weights.yml`.

Скрипт смотрит **только** на файлы и историю коммитов. Содержимое файлов не
сохраняется: в снимок попадает лишь итог проверки (число).

## Как считаются процент, этап и флаги

- **Доля этапа** = Σ(вес пункта × оценка) / Σ(вес подходящих пунктов).
- **Процент** = Σ(вес этапа × доля этапа) / Σ(весов этапов) × 100.
- **Этап пройден**, если его доля ≥ `stage_done` (0,75). **Текущий этап** — первый
  не пройденный по порядку (Старт → План → Данные → Защита → Запуск → Demo Day).
  Пройти «Защиту», перепрыгнув «Данные», нельзя: этап считается по порядку.
- **«застрял N раб. дн.»** — нет коммитов `stall_days` **рабочих** дней (пн–пт) или
  процент не растёт столько же рабочих дней по прошлым снимкам; N — большее из двух.
  У участника 4–6 часов в неделю, поэтому выходные не считаются. `stall_workdays: false`
  в `weights.yml` — считать календарные дни («застрял N дн.»).
- **«отстаёт»** — процент ниже плана на `behind_margin` пунктов. План — по
  дате старта **потока участника** (`schedule.cohorts.<поток>.start_date`, иначе
  общий `schedule.start_date`) и `expected_end_of_week`. Дата не задана —
  сравнение с серединой (медианой) его потока с запасом `median_margin`.
- **«впереди»** — выше плана на `ahead_margin` (или медианы на `median_margin`).
- **«нет доступа»** — репозиторий не найден или токен его не видит.
- **Что дальше** — первые два невыполненных пункта по порядку курса и их навык.

Активность: коммиты в ветке за 7 дней, дней с последнего коммита, число веток,
открытые pull request (только через GitHub; локально — «—»).

## Сервис в подпапке (колонка `path`)

Все пункты ищутся внутри подпапки, как будто это корень репозитория; файлы
соседних сервисов не засчитываются. Исключение — `ci`: файл в
`.github/workflows/` в корне репозитория засчитывается каждому сервису.
Коммиты за 7 дней и «дней с последнего коммита» — только по коммитам, которые
меняли эту подпапку (GitHub: `commits?path=`, локально: `git log -- <path>`),
поэтому сервис, которого не трогали 10 дней, получает «застрял 10 дн.», даже
если в соседней подпапке работа идёт каждый день. Ветки и pull request — общие
для репозитория.

## Сравнение потоков

- **Средний %** потока — среднее процентов участников потока (без «нет доступа»).
- **Медиана** — середина ряда процентов; при чётном числе — среднее двух средних.
- **Доля на этапе** — сколько участников потока сейчас на этом этапе (текущий,
  первый не пройденный; «Всё готово» — все этапы пройдены), от числа участников
  с данными. Сумма по строке — 100%.
- **Линия потока по дням** — средний % потока в каждом снимке. По горизонтали
  дни от `start_date` потока, если дата известна у всех потоков на графике,
  иначе календарная дата.

## Команда AIRL: репозиторий хаба (неделя 0)

Строка списка с `mode` = `airl` — репозиторий хаба команды AIRL. Его участником
курса не считаем: в средние, медианы, воронку и флаги потока он не входит, в отчёте
это отдельный блок «Команда AIRL: готовность хаба». Пункты (каждый 0..1, процент —
среднее):

|---|---|---|
| `scope_signed` | `SCOPE.md` | строка «Утвердил» с именем и датой (0,5 — файл без подписи) |
| `company_map` | `COMPANY_MAP.md` в корне | есть |
| `login_contract` | в карте, раздел 8, строка «Публичные ключи (JWKS)» | заполнена |
| `dev_env` | в карте, раздел 8, строка «Тестовое хранилище» | заполнена (не «[кто]») |

| `devops_md` | `DEVOPS.md` | от 300 байт |
| `hub_registry` | `hub/services.json` | корректный JSON |
