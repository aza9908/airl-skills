# Журнал проверок (`inspection-journal`)

**Боль.** Проверки качества, санитарии или оборудования ведутся в бумажном журнале
или таблице. Непроверенные партии никто не видит, отклонённые «теряются», решения
по ним принимаются в мессенджере, а через месяц невозможно понять, кто, что
и когда решил.

**Кто пользуется.** Контролёр (вводит результаты), руководитель участка (решает
судьбу отклонённого), руководитель (видит долю брака и хвост непроверенного).

**Приставка таблиц:** `insp_`

## Что закрывает

Типовые требования, которые закрываются настройкой этого модуля:

- перенос рабочей таблицы контроля в цифровой журнал;
- чек-лист проверки по шаблону: числовые замеры с допусками, «годен / не годен»,
  текст, выбор из списка;
- напоминания о партиях без проверки и просроченных проверках;
- реестр отклонённых партий с решением: карантин, переработка, разрешённая
  реализация, списание;
- отчёт: сколько произведено, проверено, одобрено, отклонено;
- стабильность показателя относительно стандарта по продукту (например, цвет
  обжарки по SKU);
- журнал корректирующих и предупреждающих действий.

Пример соответствия: в ТЗ STEP COFFEE это ROAST-001, 006, 007, 009, 010, 015, 016, 017;
в клинике — журнал санитарных проверок кабинетов и поверки оборудования.

## Настройка — вопросы

Задавай по одному, с вариантами и рекомендацией. Ответы — в `airl_settings`
(`module = 'inspection-journal'`).

| № | Вопрос | Ключ | По умолчанию |
|---|---|---|---|
| 1 | Что проверяем: партии продукции · помещения · оборудование · поставки | `object_type` | партии |
| 2 | Откуда берутся объекты проверки: учётная система или программа производства (например Cropster) · вносим вручную | — (адаптер `src_inspection_objects`) | из системы |
| 3 | Какие пункты в чек-листе: числа с допусками, «годен / не годен», текст | шаблон в `insp_templates` и `insp_template_items` | по журналу клиента |
| 4 | Через сколько часов после производства объект считается «без проверки» | `overdue_hours` | 24 |
| 5 | Какие решения возможны по отклонённому | `dispositions` | карантин, переработка, разрешённая реализация, списание |
| 6 | Кто принимает решение по отклонённому | роль из карты или `SPEC.md` | руководитель участка |
| 7 | Пороги светофора для доли отклонений | `reject_warn`, `reject_bad` | 3% и 7% |

Шаблон чек-листа составляй **по реальному журналу клиента**: попроси фото или файл
текущей таблицы и перенеси столбцы как пункты. Не придумывай пункты сам.

## Данные

**Вход** — представление `src_inspection_objects`, которое пишет `/airl-dwh` или
`/airl-connect`:

| Колонка | Тип | Что |
|---|---|---|
| `object_id` | text | ключ объекта в источнике (номер партии, PR, код кабинета) |
| `object_type` | text | тип из вопроса 1 |
| `title` | text | как показать на экране |
| `sku` | text | продукт или вид объекта (для стабильности по продукту) |
| `lot` | text | партия сырья, если есть |
| `produced_at` | timestamptz | когда объект появился и стал требовать проверки |
| `produced_by` | text | кто произвёл (обжарщик, смена) |
| `branch_id` | text | подразделение, если их несколько |

**Таблицы модуля:** `insp_templates`, `insp_template_items`, `insp_checks`,
`insp_results`, `insp_actions`.

**Статусы проверки** (`insp_checks.status`):

```text
draft ──► passed
  └────► rejected ──► (решение disposition) quarantine | rework | conditional_release | written_off
```

`passed` и `rejected` ставит контролёр; `disposition` — только роль из вопроса 6.
Каждая смена — строка в `airl_audit`.

**Персональные данные:** нет (имена сотрудников — только идентификаторы пользователей).

## Экраны

1. **«Ждут проверки»** — главный экран контролёра. Список объектов без проверки,
   просроченные сверху и красным. Главная кнопка: **«Проверить»**.
   Пусто: «Все партии проверены. Новые появятся здесь автоматически».
2. **«Проверка»** — чек-лист по шаблону: числовые поля с допуском рядом
   («цель 62, допуск 60–64»), значение вне допуска подсвечивается сразу.
   Кнопки: **«Годен»** · **«Отклонить»** (обязателен комментарий).
3. **«Отклонённые»** — реестр с решением. Для роли из вопроса 6 кнопка
   **«Принять решение»** со списком из вопроса 5.
4. **«Стабильность»** — по продукту: последние 30 значений числового пункта
   относительно цели и допуска.

Ошибка сети на экране проверки: «Не удалось сохранить проверку. Данные остались
в форме — нажмите «Сохранить» ещё раз».

## Роли

| Действие | Контролёр | Руководитель участка | Руководитель |
|---|---|---|---|
| видеть журнал | да | да | да |
| вносить проверку | да | да | нет |
| решение по отклонённому | нет | да | нет |
| менять шаблон чек-листа | нет | да | нет |

## Показатели

| id | Формула | Светофор |
|---|---|---|
| `qc_reject_rate` | отклонённые / все завершённые проверки за месяц, по дате проверки | `reject_warn`, `reject_bad` (меньше — лучше) |
| `qc_unchecked_overdue` | объекты без проверки старше `overdue_hours` на текущий момент | 0 — зелёный, 1–3 — жёлтый, больше — красный |

В хабе оба `id` должны быть в разделе 4 карты.

## Что уходит в хаб

`qc_reject_rate` и `qc_unchecked_overdue`; предупреждение — число отклонённых без решения.

## Уведомления

- объект без проверки дольше `overdue_hours` — контролёру смены, один раз на объект;
- отклонение — руководителю участка, сразу.

## Приёмка

- [ ] шаблон чек-листа совпадает с текущим журналом клиента (проверил руководитель участка);
- [ ] объект из источника появляется в «Ждут проверки» не позже следующей загрузки;
- [ ] значение вне допуска подсвечивается до сохранения;
- [ ] «Отклонить» без комментария не сохраняется;
- [ ] решение по отклонённому недоступно контролёру (проверено запросом под его ролью);
- [ ] `qc_reject_rate` за прошлый месяц совпадает с ручным подсчётом по старому журналу.

## После курса

Жалобы клиентов с привязкой к партии (модуль `complaints`), прослеживаемость
от сырья до клиента, автоматический импорт замеров с приборов.

## Ловушки

- Объект проверяют дважды (повторная проверка после переработки) — в долю брака
  идёт **последняя** завершённая проверка объекта.
- Шаблон меняется — старые проверки остаются со старым шаблоном (`template_id`
  в проверке), отчёты не ломаются.
- Время производства в источнике часто без часового пояса — уточни при адаптере.
