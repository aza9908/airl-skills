# airl-context — память проекта и экономия токенов

## Почему лимиты сгорают (скажи человеку своими словами, 3–4 предложения)

Модель не помнит прошлые сообщения сама: перед **каждым** ответом она заново читает
всю историю чата — все сообщения, файлы и логи, которые в нём были. Чат на 200 сообщений
обходится в разы дороже, чем 10 коротких чатов по 20 сообщений. Поэтому главная экономия —
не модель и не тариф, а **короткие чаты с хорошей памятью проекта в файле**. Эта память —
`CLAUDE.md`: Claude Code читает его сам в начале каждого чата, ничего вставлять не нужно.

## Как вести человека

- Вопросы по одному, с вариантами и рекомендацией. Термины — с пояснением в скобках.
- Перед необратимым (push в основную ветку, удаление веток) — спроси «да?».
- Значения ключей и паролей никогда не пиши в `CLAUDE.md` — только где они лежат.

## Режим 1. Начать проект — создать CLAUDE.md

1. Посмотри, что уже есть: `CLAUDE.md`, `SPEC.md`, `ARCHITECTURE.md`, `COMPANY_MAP.md`,
   `PRD_CONTEXT.md`, `DWH.md`, `DEVOPS.md`, `README.md`, `package.json`/`pyproject.toml`,
   `git log --oneline -10`. Не читай файлы целиком без нужды — заголовки и первые строки.
2. `CLAUDE.md` есть — не затирай: предложи дополнить недостающие разделы.
3. Проверь, что проект в git и есть удалённый репозиторий на GitHub. Нет — предложи
   создать (это страховка: история изменений и откат).
4. Создай `CLAUDE.md` по шаблону ниже. **Не больше 150 строк**: он читается в каждом
   чате, и каждая лишняя строка стоит токенов каждый раз. Подробности — ссылками на
   документы, а не копией.
5. Закоммить и запушь. Скажи: «Теперь каждую новую задачу начинайте в новом чате».

```markdown
# [Название продукта] — контекст проекта

> Читать первым. Обновляется в конце каждой задачи (`/airl-context закончить задачу`).

## Что это
1–3 предложения: продукт, для кого, какая боль. Владелец: [имя, должность].

## Документы (читать по необходимости, не целиком)
- `SPEC.md` — ТЗ · `ARCHITECTURE.md` — схема и стек · `PRD_FINAL.md` — полный PRD
- `COMPANY_MAP.md` (или `airl/COMPANY_MAP.md`) — карта компании, показатели, роли
- `DWH.md`, `SECURITY.md`, `DEVOPS.md`, `REVIEW.md`, `DEBUG.md`

## Стек и запуск
- Стек: …
- Запуск локально: `…` · Тесты: `…` · Выкладка: `…`
- Ключи: в `.env` (в git не попадает), образец — `.env.example`

## Правила проекта
- [5–10 строк: что нельзя, как называем, куда пишет сервис, язык интерфейса]

## Состояние (обновлять в конце задачи)
- Сделано: …
- В работе: …
- Следующий шаг: …
- Известные проблемы: …

## Журнал задач (последние 10, старые удалять)
| Дата | Задача | Ветка | Итог |
|---|---|---|---|
```

## Режим 2. Начать задачу

Человек открыл **новый чат** и пишет: «начни задачу: <что>». Сделай:

1. Прочитай `CLAUDE.md` (Claude Code уже подгрузил его — не перечитывай заново, если он
   в контексте). Из документов открой только нужные для этой задачи разделы.
2. Создай ветку: `git checkout -b <тип>/<коротко>` (`feat/`, `fix/`, `docs/`), от свежей
   основной ветки (`git pull` перед этим).
3. Скажи одной фразой план и чего задача **не** касается — чтобы не расползалась.

Если человек продолжает старый длинный чат с новой задачей — предложи: «Эта задача
новая. Начнём её в новом чате? Я сначала обновлю `CLAUDE.md`, чтобы ничего не потерять».

## Режим 3. Закончить задачу

1. Проверь: тесты прошли, отладочного кода нет, ключей в изменениях нет.
2. Закоммить с понятным сообщением.
3. Обнови `CLAUDE.md`: раздел «Состояние» и строка в «Журнале задач» (старше 10 —
   удалить). Изменились команды, стек, правила — поправь соответствующий раздел.
4. Запушь ветку. В основную ветку — через pull request или слиянием, **после «да»**
   человека (в проектах курса AIRL основная ветка — та, что выкладывается на сервер).
5. Скажи: «Готово. Следующую задачу начните в новом чате — я вспомню всё из `CLAUDE.md`».

## Режим 4. Экономия — правила (покажи человеку, если просит или жалуется на лимит)

**Главное**
- Одна задача — один чат. Закончили — новый чат. Память — в `CLAUDE.md`, а не в истории.
- Чат всё равно разросся — команда `/compact` сжимает историю в краткую выжимку;
  `/clear` очищает чат полностью (после обновления `CLAUDE.md`). `/context` показывает,
  чем занят контекст.
- Не вставляй в чат длинные логи, таблицы и целые файлы. Дай путь к файлу или последние
  30–50 строк ошибки.

**Модель и рассуждения**
- Рутинное (переименовать, поправить текст, простые правки, повторяющиеся шаги) —
  более быстрая и дешёвая модель (`/model`), низкий или средний уровень рассуждений.
- Сложное (архитектура, хитрая ошибка, безопасность, миграции базы) — сильная модель
  и высокий уровень рассуждений, но в коротком чате с точной задачей.
- Не включай максимальный уровень «на всякий случай»: он тратит в разы больше.

**Как просить**
- Точная задача с границами: «в `src/orders/list.tsx` добавь фильтр по статусу,
  остальное не трогай» дешевле, чем «сделай фильтры».
- Сразу дай, где искать: файл, функцию, экран. Иначе модель читает пол-проекта.
- Большая задача — сначала план (режим планирования), потом выполнение по частям,
  каждая часть — коммит.

**Что делает сам Claude (правило для всех навыков AIRL)**
- Читает файлы частями и ищет поиском, а не открывает всё подряд.
- Не печатает в ответ огромные файлы и выводы команд — только суть и пути.
- Широкий поиск по коду отдаёт помощнику (субагенту): в основной чат возвращается вывод,
  а не сотни строк.
- Не перечитывает то, что уже прочитал в этом чате.

## Чего не делать

- Не раздувать `CLAUDE.md`: больше 150 строк — сожми, перенеси подробности в документы.
- Не хранить в `CLAUDE.md` ключи, пароли, персональные данные.
- Не пушить в основную ветку без «да».
- Не продолжать в одном чате разные задачи, когда можно начать новый.
