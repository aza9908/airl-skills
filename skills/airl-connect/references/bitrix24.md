# Bitrix24: что закрывает и как забирать данные

Справочник для `/airl-connect`. Названия разделов меню и доступность возможностей
зависят от версии и тарифа и меняются. Каждый пункт, помеченный «проверить», —
подтвердить у администратора клиента в его кабинете и на сайте Bitrix24 в день
выбора тарифа. Облако (`<портал>.bitrix24.kz`, `.ru`, `.com`) и коробочная версия
(на своём сервере) отличаются; для персональных данных, которые закон требует
хранить в стране, коробка на своём сервере — вариант, который стоит обсудить.

Чего Bitrix24 не закрывает в духе ТЗ производства и склада: журнал контроля
качества партий, дебиторка из 1С с возрастом долга, склад со сканерами и адресным
хранением — это модули (`inspection-journal`, `receivables`, `stock-levels`)
или отдельная складская система.

## Данные в хаб: REST API

**Доступ.** Входящий вебхук: Разработчикам → Другое → Входящий вебхук (путь —
проверить в версии клиента). Создаётся **от технического пользователя** с правами
только на нужные разделы; при создании выбираются права (scope): `crm`, `task`,
`user`, `department`. Адрес вида `https://<портал>/rest/<id пользователя>/<код>/` —
это секрет: кто знает адрес, тот читает данные. Хранить в `.env` на сервере,
переменная `BITRIX24_WEBHOOK_URL`.

**Методы списков** возвращают по 50 записей: параметр `start` — с какой записи,
в ответе `next` — следующая страница и `total`. Фильтр по изменению — поле
`DATE_MODIFY` (у задач — `CHANGED_DATE`), с префиксом `>=`.

| Сущность в `extract.py` | Метод | Ключ записи | Поле изменения |
|---|---|---|---|
| `deals` | `crm.deal.list` | `ID` | `DATE_MODIFY` |
| `leads` | `crm.lead.list` | `ID` | `DATE_MODIFY` |
| `companies` | `crm.company.list` | `ID` | `DATE_MODIFY` |
| `contacts` | `crm.contact.list` | `ID` | `DATE_MODIFY` |
| `activities` | `crm.activity.list` | `ID` | `LAST_UPDATED` |
| `tasks` | `tasks.task.list` (ответ в `result.tasks`, поля в виде `id`, `changedDate`) | `id` | `CHANGED_DATE` |
| `users` | `user.get` | `ID` | — (полная выгрузка) |
| `departments` | `department.get` | `ID` | — (полная выгрузка) |
| `deal_stages` | `crm.status.list` с фильтром по `ENTITY_ID` | `ID` | — |

Смарт-процессы — `crm.item.list` с параметром `entityTypeId` (ответ в
`result.items`) — добавляются в `extract.py` по образцу задач.

**Лимиты.** Облако ограничивает частоту запросов (порядка 2 в секунду на портал,
при превышении — ошибка `QUERY_LIMIT_EXCEEDED`; точные значения — проверить в
документации). `extract.py` делает паузу между запросами и повторяет запрос
с нарастающей паузой при перегрузке.

**Пользовательские поля** приходят как `UF_CRM_...`. Чтобы знать, что это за поле,
выгрузи справочник `crm.deal.fields` один раз и сохрани соответствие кода
и названия в `DWH.md`.

## Представления `core` над выгрузкой (пример)

После `load.sh` записи лежат в `raw_bitrix24.records` (`entity`, `source_id`,
`payload jsonb`). Пример представлений:

```sql
CREATE OR REPLACE VIEW core.crm_deals AS
SELECT
    'bitrix24:' || r.source_id                              AS deal_id,
    r.payload->>'TITLE'                                     AS title,
    r.payload->>'COMPANY_ID'                                AS company_source_id,
    r.payload->>'STAGE_ID'                                  AS stage_id,
    (r.payload->>'OPPORTUNITY')::numeric(18,2)              AS amount,
    r.payload->>'CURRENCY_ID'                               AS currency,
    r.payload->>'ASSIGNED_BY_ID'                            AS manager_source_id,
    (r.payload->>'DATE_CREATE')::timestamptz                AS created_at,
    (r.payload->>'CLOSEDATE')::timestamptz                  AS close_date,
    r.payload->>'SOURCE_ID'                                 AS source,
    r.payload->>'UTM_CAMPAIGN'                              AS utm_campaign
FROM raw_bitrix24.records r
WHERE r.entity = 'deals' AND NOT r.is_deleted;
```

Сделка и выручка — разные вещи: «выручка» карты считается по 1С (оплаты или
отгрузки), а сделки CRM — для воронки и конверсии. Не смешивай.

## Удалённые записи

Методы списков не возвращают удалённое. Раз в сутки выгружай полный список ID
(`select: ['ID']`) и помечай пропавшие `is_deleted = true` — `load.sh` это умеет
(режим полной выгрузки сущности).
