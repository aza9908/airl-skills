# Готовность к продакшену: чек-лист

Один список для трёх случаев: финальная проверка в `/airl-devops`, приёмка сервиса
в хаб (`/airl-hub`, режим B2) и сводка готовности к Demo Day. Каждый пункт проверяется
**действием или файлом**, а не словами «да, сделали».

Столбец «Нужно»: **Д** — обязательно к Demo Day для любого продукта; **2+** — для уровня 2
и выше из `airl-context` или если продукт хранит персональные данные; **3** — уровень 3.
Столбец «Хаб» — номер ворот `/airl-hub`, которые закрывает пункт.

## Как записать результат

В `DEVOPS.md` — раздел:

```markdown
## Готовность к продакшену — ГГГГ-ММ-ДД, коммит [хеш]

**Уровень**: [1/2/3] · **Итог**: готов / готов с оговорками / не готов
**Не выполнено из обязательного (Д)**: [номера или «нет»]
**Не выполнено для уровня**: [номера, срок]

| № | Итог | Комментарий |
|---|---|---|
| ПР-1 | да | REVIEW.md от ГГГГ-ММ-ДД, коммит … |
```

**Правило итога:** хотя бы один пункт **Д** не выполнен — «не готов» к открытию людям
и к Demo Day. Пункты уровня 2+ и 3 — «готов с оговорками» и сроком, если руководитель
согласен.

Для сводки Demo Day (`/airl-hub`, режим C) достаточно столбца «Нужно = Д» по каждому
сервису: число выполненных из обязательных и номера невыполненных.
