# Навыки AIRL

Навыки для Claude в VS Code. Каждый навык **сам задаёт вопросы** — по одному,
с готовыми вариантами ответа и рекомендацией. Отвечать можно одной буквой.
Технических знаний не требуется.

Установка — две команды, см. раздел [Установка](#установка).

Без навыков ИИ пишет прототип. С навыками получается боевой продукт.

## Что внутри — коротко

**Для участников курса VibeOps** — ведут сотрудника от рабочей задачи до боевого
продукта за 4 недели. Человек отвечает на вопросы, навык делает остальное.

| Навык | Простыми словами |
|---|---|
| `/airl-spec` | Разбирает задачу или ТЗ компании: что болит, сколько это стоит, что делаем в курсе, что потом. Пишет понятное техническое задание и схему продукта |
| `/airl-modules` | Даёт готовые модули вместо разработки с нуля: журналы проверок, согласования, дебиторка, клиенты под риском, склад, доставка, закупки, запись клиентов и другие |
| `/airl-connect` | Подключает готовые системы (Bitrix24, amoCRM) вместо написания своих: что настроить и где нажать, плюс данные в общее хранилище |
| `/airl-dwh` | Строит базу данных и общее хранилище компании, подключает 1С и другие системы |
| `/airl-pwa` | Собирает приложение, которое удобно открывать с телефона, и Telegram-бота |
| `/airl-cybersecurity` | Вход по логину и роли, защита ключей и персональных данных, проверка взломом |
| `/airl-devops` | Сервер, домен, автоматическая выкладка из GitHub с откатом, копии, мониторинг |
| `/airl-ai` | ИИ-помощник руководителя: утренняя сводка в Telegram, ответы на вопросы о цифрах и по регламентам. Цифры не выдумывает: каждое сверяется с базой |
| `/airl-hub` | Собирает сервисы всех отделов в один экран руководителя с одним входом |
| `/airl-architecture-extra` | Дополнение к схеме продукта, когда в нём несколько сервисов, очередь или файлы |
| `/airl-debug` | Когда «что-то сломалось»: собирает симптомы, находит, где живёт ошибка, чинит причину, а не симптом, и добавляет тест, чтобы она не вернулась. После трёх неудачных попыток зовёт инженера |

**Суперскиллы для команды AIRL** — уровень senior-разработчика и DevOps. Ими инженеры
AIRL ведут «инженерный трек» параллельно с курсом и закрывают то, что участникам
не по силам:

| Навык | Простыми словами |
|---|---|
| `/airl-integrations` | Связывает продукт с внешним миром надёжно: запись обратно в 1С, банковские выписки, маркетплейсы (Kaspi, Uzum, Ozon, WB), платежи (Payme, Click, Kaspi Pay), телефония, Cropster, мессенджеры. Без потерь и дублей при сбоях, со сверкой каждый день |
| `/airl-code-review` | Проверяет код перед запуском как senior-разработчик: автоматические проверки, тесты, безопасность, миграции базы, скорость. Объясняет находки простыми словами и пишет `REVIEW.md` для приёмки |
| `/airl-devops` (уровень продакшена) | Тестовая и боевая среда, проверки качества перед каждой выкладкой, миграции без остановки, мониторинг и оповещения, восстановление базы на любой момент, инструкции на случай аварий |
| Библиотека модулей | 17 модулей с проверенной на PostgreSQL схемой, включая склад с камерой телефона вместо сканеров, банковскую сверку, прибыль и убытки, лиды со сквозным ID, прогноз спроса *(7 новых — в работе)* |

**Для инженеров: общие навыки по стеку.** Навыки AIRL отвечают за путь курса и правила
хаба, а не за сам язык программирования. Инженерам AIRL удобно поставить рядом открытые
(MIT) навыки из [simplevaad-debug/superskills](https://github.com/simplevaad-debug/superskills):
`python-pro`, `typescript-pro`, `react-expert`, `docker-development`, `test-master`,
`api-designer`, `debugging-wizard`. Они на английском, конфликтов имён с `airl-*` нет.
Лучшее из `debugging-wizard`, `test-master` и `api-designer` уже перенесено в
`/airl-debug` и `/airl-code-review`.

```bash
git clone https://github.com/simplevaad-debug/superskills.git /tmp/superskills
cp -r /tmp/superskills/skills/{python-pro,typescript-pro,react-expert,docker-development,test-master,api-designer,debugging-wizard} ~/.claude/skills/
```

## VibeOps: 4 недели до боевого продукта

| Неделя | Навык | Что делает | Что остаётся в репозитории |
|---|---|---|---|
| 1 · План | `/airl-spec` | Превращает задачу в настоящий PRD и схему архитектуры. Начинает с боли и её цены в цифрах, чтобы на Demo Day показать «было → стало» | `SPEC.md`, `ARCHITECTURE.md` |
| 1 · План | `/airl-architecture-extra` | Только если в продукте несколько сервисов, очередь, файлы или несколько баз: связи, надёжность, уровень сложности с ценой | дополняет `ARCHITECTURE.md` |
| 1–2 · План и данные | `/airl-modules` | **Готовые модули вместо сборки с нуля**: журнал проверок качества, согласование заявок, дебиторка, клиенты под риском, план/факт, остатки и дефицит, заявки на ремонт, онбординг и обучение, запись и напоминания, обращения с SLA. Участник настраивает модуль, а не строит | модули в базе, экраны |
| 1–2 · План и данные | `/airl-connect` | **Купить и подключить**: закрывает типовые требования готовой системой (Bitrix24, amoCRM) — план настройки для администратора с путями в меню и выгрузка данных системы в хранилище | `CONNECT.md` |
| 2 · Данные | `/airl-dwh` | Проектирует базу и хранилище до кода, пишет миграции и подключает данные и внешние API к продукту | `DWH.md`, миграции |
| 2 · Данные | `/airl-pwa` | Собирает продукт как PWA: с телефона, установка на экран, работа без сети, все состояния экранов | код продукта |
| 3 · Защита | `/airl-cybersecurity` | Добавляет вход и роли, проверяет ключи и персональные данные. Проверяет не чтением кода, а попытками взлома | `SECURITY.md` |
| 4 · Запуск | `/airl-code-review` | Проверка кода перед запуском: тесты, ключи в коде, миграции базы, Docker; находки простыми словами | `REVIEW.md` |
| 4 · Запуск | `/airl-devops` | Сервер, домен, сертификат, резервные копии, автоматическая выкладка из GitHub с откатом, памятка по серверу | `DEVOPS.md` |
| 4 · Запуск | `/airl-ai` | **ИИ-помощник поверх единых цифр**: утренняя сводка руководителю в Telegram, ответы на вопросы о цифрах и по регламентам со ссылкой на источник. ИИ не может выдумать цифру: каждое число сверяется с базой | `AI.md` |
| 4 · Запуск | `/airl-hub` | Только для компаний с хабом: создаёт хаб, проверяет сервисы отделов по 13 воротам и собирает их в один продукт | `HUB_CHECK.md` |

Каждый навык читает документы предыдущих и не спрашивает то же самое второй раз.

**Как большое ТЗ укладывается в курс.** `/airl-spec` раскладывает каждое требование
клиента по шести корзинам: готовый модуль, готовая система, ИИ-слой, своя сборка,
инженерный трек команды AIRL и «после курса». Своя сборка — только то, что уникально
для компании; типовое закрывают модули и готовые системы, сложное — инженеры AIRL. Итог — число «сколько требований закрываем
в курсе» с подписью руководителя до первой недели.

### Путь 1. Свой продукт на своём домене

У каждого участника своя рабочая задача. Откройте пустую папку проекта и идите
по порядку:

```
/airl-spec «учёт звонков клиентам для отдела продаж»   ← неделя 1
/airl-modules                                          ← неделя 1–2, если есть подходящие модули
/airl-dwh                                              ← неделя 2
/airl-pwa                                              ← неделя 2
/airl-cybersecurity                                    ← неделя 3
/airl-devops                                           ← неделя 4
```

Уже есть прототип (`DESIGN.md`, `ARCHITECTURE.md` или просто код)? Запустите в его папке
`/airl-spec апгрейд` — навык сохранит экраны и технологии и покажет, чего не хватает
до боевого продукта.

### Путь 2. Сервисы отделов в хабе руководителя

Данные компании лежат в 1С, Bitrix24, amoCRM и таблицах. Команда AIRL один раз
собирает их в общее хранилище, отделы строят на нём свои сервисы, а хаб объединяет
сервисы на одном экране руководителя.

```text
              COMPANY_MAP.md  ← /airl-spec карта (одна на всю компанию)
                    │
   ┌────────────────┼──────────────────────────────┐
   хранилище      ТЗ сервиса каждого отдела = ветка карты
   /airl-dwh      SPEC.md + airl.service.json
                    │
        /airl-pwa → /airl-cybersecurity → /airl-devops
                    │
                 /airl-hub — проверяет сервис по контракту и подключает к хабу
```

```
Команда AIRL, в репозитории хаба:

/airl-spec карта            ← неделя 1, вместе с руководителем
/airl-devops                ← сервер и прокси — до недели 2 отделов
/airl-dwh                   ← общее хранилище: core, metrics, витрины — до недели 2
/airl-hub создать хаб       ← вход и тестовые пользователи — до недели 3
/airl-hub принять sales     ← неделя 4, приёмка каждого сервиса
/airl-hub готовность        ← перед Demo Day

Каждый отдел, в репозитории своего сервиса:

/airl-spec ТЗ отдела продаж ← неделя 1
/airl-dwh                   ← неделя 2, витрина отдела
/airl-pwa                   ← неделя 2
/airl-cybersecurity         ← неделя 3
/airl-devops                ← неделя 4, выкладка на сервер хаба без остановки соседей
/airl-hub самопроверка      ← неделя 4, заявка на приёмку
```

Навыки сами понимают, какой путь: есть карта компании — работают как часть хаба,
нет — ведут отдельный продукт.

Правила хаба, которые навыки соблюдают на каждом шаге: одни цифры для всех (выручка,
заявка и клиент считаются по определениям из карты), данные из одного места (1С и CRM
работают как раньше), одна карточка клиента, свой участок у отдела (сервис пишет только
в свою витрину — это закреплено правами в базе), один вход и роли, обновления
с проверкой и откатом одной командой.

Проверить контракт сервиса перед приёмкой можно самому: запустите
`/airl-hub самопроверка` в репозитории сервиса.

## Установка

Нужно один раз. После этого навыки работают во всех ваших проектах.
Есть два способа. Первый проще и сам обновляется по одной команде.

### Способ 1. Плагин Claude Code — рекомендуем

**Шаг 1.** Откройте VS Code и установите расширение **Claude Code** от издателя
**Anthropic**: значок с квадратиками слева (Extensions) → в поиске `Claude Code` →
Install. Справа появится значок Claude — нажмите и войдите в свой аккаунт.

**Шаг 2.** Откройте терминал: меню **Terminal → New Terminal**. Вставьте первую
команду и нажмите Enter — она подключает каталог навыков AIRL:

```bash
claude plugin marketplace add aza9908/airl-skills
```

**Шаг 3.** Вставьте вторую команду — она ставит сами навыки:

```bash
claude plugin install airl@airl-skills
```

Должно появиться `Successfully installed plugin: airl@airl-skills`.

**Шаг 4.** Перезагрузите окно: **Cmd + Shift + P** (на Windows **Ctrl + Shift + P**),
наберите `Developer: Reload Window`, нажмите Enter.

**Шаг 5.** Проверьте. В панели Claude справа наберите:

```
/airl
```

Под полем появится список навыков с описаниями на русском. Выберите нужный —
например `/airl:airl-spec`. Значит, всё готово.

То же самое можно сделать без терминала, прямо в панели Claude: наберите `/plugins`,
на вкладке Marketplaces добавьте `aza9908/airl-skills`, на вкладке Plugins
установите `airl`.

> **Как называются команды.** У навыков из плагина перед именем стоит имя плагина:
> `/airl:airl-spec`, `/airl:airl-dwh`. В описаниях выше они для
> краткости записаны как `/airl-spec`, `/airl-dwh`. Можно и вовсе без
> команды: напишите Claude «запусти навык airl-spec».

### Способ 2. Копирование файлов

Подходит, если плагины в вашей версии недоступны. Нужен установленный
[git](https://git-scm.com). В терминале VS Code:

```bash
cd ~/Downloads && git clone https://github.com/aza9908/airl-skills.git && cd airl-skills && bash install.sh
```

Должно появиться `Готово. Установлены навыки: …`. Затем перезагрузите окно
(шаг 4 выше) и наберите в панели Claude `/airl-spec`. При этом способе команды
короткие, без приставки: `/airl-spec`, `/airl-dwh`.

Ставьте одним способом, а не обоими: иначе каждый навык появится в списке дважды.

## Если что-то не работает

**Навыки не появились после установки.**
Перезагрузите окно VS Code (шаг 4). Если не помогло, проверьте в терминале:

```bash
claude plugin list
```

Должна быть строка `airl@airl-skills` со статусом `enabled`. Её нет — повторите
шаги 2 и 3.

**Ошибка `command not found: claude`.**
Команда `claude` ставится вместе с Claude Code. Установите его по инструкции на
[claude.com/claude-code](https://claude.com/claude-code) или добавьте плагин через
панель Claude (`/plugins`), или воспользуйтесь способом 2.

**Пишу `/airl` в терминале, ничего не происходит.**
Навыки набираются в панели Claude справа, а не в чёрном терминале снизу.

**Ошибка `command not found: git`** (способ 2).
Установите git с [git-scm.com](https://git-scm.com) и повторите команду.

**Claude отвечает не на русском.**
Напишите ему: «Отвечай на русском языке».

## Обновление

Плагин (способ 1):

```bash
claude plugin marketplace update airl-skills
```

```bash
claude plugin update airl@airl-skills
```

Копирование (способ 2):

```bash
cd ~/Downloads/airl-skills && git pull && bash install.sh
```

Старые навыки однодневного блока (`/design`, `/architecture`, `/security`) из набора
убраны. Если ставили копированием, удалите их:

```bash
rm -rf ~/.claude/skills/design ~/.claude/skills/architecture ~/.claude/skills/security
```

И снова перезагрузите окно VS Code.

## Удаление

Плагин (способ 1):

```bash
claude plugin uninstall airl@airl-skills
```

Копирование (способ 2):

```bash
rm -rf ~/.claude/skills/airl-*
```

Ваши проекты не пострадают — удаляются только навыки.

## Для тех, кто развивает навыки

Проверки, которые должны проходить перед каждым обновлением `main`:

```bash
DATABASE_URL=<пустая тестовая база PostgreSQL 16> bash skills/airl-modules/scripts/test_modules.sh
```

Ставит каждый модуль в чистую схему дважды, все модули вместе в одну схему,
проверяет экраны и показатели и чтение показателей из другой схемы. Создаёт
и удаляет схемы `test_airl_*` — только на тестовой базе.

```bash
pip install anthropic "psycopg[binary]" && TEST_DATABASE_URL=<тестовая база> python3 tests/test_airl_ai.py
```

Проверяет ИИ-слой без вызова модели: сверку чисел, повтор и отказ модели, роли,
базу знаний.

```bash
claude plugin validate .
```

Проверяет манифест плагина и каталога.
