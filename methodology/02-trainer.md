# Тренер и куратор сопровождения

Эта инструкция — для тренера курса VibeOps. Тренер ведёт группу от офлайн-дня
до Demo Day: следит за прогрессом, снимает блокеры (то, что мешает двигаться),
принимает этапы и вовремя зовёт инженера.

Главный инструмент — навык `/airl-progress` (смотрит репозитории участников
и считает процент и этап). Он только читает: ничего не меняет и код
не скачивает.

## Ваша неделя

| Когда | Что | Сколько времени |
|---|---|---|
| Каждое утро | сводка `/airl-progress` и сообщения по флагам | 20–30 мин |
| Вторник | групповой созвон: план недели, разбор типичных ошибок | 60 мин |
| Четверг | групповой созвон: показ результатов, кто застрял — разбор | 60 мин |
| 2–3 окна в неделю | офис-часы: по записи, 15–20 мин на человека | 2–3 ч |
| Пятница | приёмка этапа: проверка содержимого, а не только процента | 1–2 ч |
| Пятница | короткий отчёт продакт-менеджеру (Алмасу) | 15 мин |

Дни можно сдвинуть. Главное — два созвона в неделю с промежутком в 2–3 дня
и одни и те же часы офис-часов, чтобы участники привыкли.

## До старта: настройка /airl-progress

Делается один раз на поток (когорту — группу, которая учится вместе).

1. Создайте отдельный репозиторий когорты (например, `vibeops-2026-11`),
   закрытый.
2. В новом чате: `/airl-progress настроить когорту`. Навык задаст 5 вопросов:
   - название потока — например, `VibeOps-2026-11`;
   - список участников — таблица `roster.csv` с колонками `name, company,
     department, mode, repo, branch, live_url, cohort, path`
     (`mode`: `solo` или `hub`);
   - дата начала недели 1 — запишется в `weights.yml`, `schedule`;
   - где запускать — рекомендуем GitHub Actions каждый день;
   - токен (пароль для программы с ограниченными правами) только на чтение.
3. Токен создаёте вы в GitHub: **Settings → Developer settings → Personal access
   tokens → Fine-grained tokens**. Права: `Contents — Read-only`,
   `Metadata — Read-only`, по желанию `Pull requests — Read-only`. Срок — до
   конца курса плюс неделя. Положите его в секрет репозитория когорты
   `PROGRESS_TOKEN`. В чат его не вставляйте.
4. Для сводки в Telegram добавьте секреты `TELEGRAM_BOT_TOKEN`
   и `TELEGRAM_CHAT_ID`.
5. **Предупредите участников**, что за прогрессом следят. Текст:

   > Раз в день программа смотрит список файлов и несколько документов в вашем
   > репозитории (ТЗ, отчёты о проверках), чтобы посчитать прогресс курса.
   > Код не копируется, содержимое не сохраняется. Отчёт видят тренеры курса.

6. Не включайте публикацию отчёта на GitHub Pages без согласия участников:
   на бесплатном тарифе такой сайт открыт всем.

В списке — минимум личных данных: имя и первая буква фамилии, компания, отдел.

**Как проверить:** первый запуск прошёл, в отчёте `report/index.html` все
участники, строк «нет доступа» нет.

## Офлайн-день: повестка

Цель дня: у каждого стоят программы, есть репозиторий на GitHub, `CLAUDE.md`,
начат `/airl-spec` и договорён замер «было». В хабе — у каждого отдела
репозиторий из шаблона и копия карты.

| Время | Что | Кто ведёт | Результат |
|---|---|---|---|
| 09:30–10:00 | Знакомство, правила курса, путь по неделям, что такое Demo Day | тренер | все знают цель и даты |
| 10:00–10:30 | Руководитель клиента: зачем компании курс, какие боли важнее (хаб: карта компании одним слайдом) | руководитель клиента, PM | участники слышат приоритеты |
| 10:30–12:00 | Установка по [00-novice.md](00-novice.md), шаги 1–6: GitHub, git, VS Code, Claude Code, плагин | тренер + помощник; инженер на сложные случаи | `/airl` показывает список навыков у всех |
| 12:00–12:30 | Репозиторий: свой — случай А; хаб — клон репозитория отдела (случай Б); тренеру доступ на чтение | тренер | ссылки у тренера, в `roster.csv` |
| 12:30–13:30 | Обед | — | — |
| 13:30–14:00 | `/airl-context начать проект`, первый commit и push | тренер | `CLAUDE.md` на GitHub |
| 14:00–14:30 | Ритуал «новая задача — новый чат», commit и push, чего нельзя (ключи, `.env`, ПДн) | тренер | шпаргалка у каждого |
| 14:30–16:00 | `/airl-spec`: боль и цена боли. Хаб — по отделам, с путём к карте | тренер, инженеры отвечают про данные | черновик раздела 1 `SPEC.md` |
| 16:00–16:30 | Замер «было»: кто, как и с какой даты меряет метрику | тренер | строка «Неделя 0 · Замер «было»» в разделе 12 |
| 16:30–17:00 | Первый запуск `/airl-progress`, итоги дня, расписание созвонов и офис-часов | тренер | ни одного «нет доступа» |

Что подготовить заранее:

- список участников с ником на GitHub и путём (solo/hub);
- для хаба — ссылки на репозитории отделов и приглашения (делает инженер, Д9 недели 0);
- запасной мобильный интернет; удлинители;
- аккаунты Claude, если их выдаёт компания или AIRL;
- 2–3 ноутбука с уже установленным набором — на случай, если чей-то
  корпоративный ноутбук не даёт ставить программы.

Кто к 17:00 не закончил установку — личные офис-часы на следующий день.
Не переносите это на неделю 1.

## Ежедневная сводка

Каждое утро в Telegram приходит короткий текст (`report/telegram.txt`):
средний процент, сколько впереди, отстают и застряли, строка по каждому потоку.

Что делать с ней:

1. Откройте отчёт (`report/index.html` из артефакта запуска или локально).
2. Посмотрите блок «Кому помочь».
3. Для подробностей в новом чате: `/airl-progress кто отстаёт`. Навык даст
   по каждому: процент, этап, почему так, что предложить и готовое сообщение.
4. Напишите каждому из списка по плейбуку ниже. Не позже обеда.

Флаги и что они значат:

| Флаг | Что значит | Порог по умолчанию |
|---|---|---|
| «застрял N дн.» | N дней нет коммитов или процент не растёт | 4 дня |
| «отстаёт» | процент ниже плана курса на 15 и больше пунктов | 15 |
| «впереди» | выше плана на 10 и больше | 10 |
| «нет доступа» | репозиторий не найден или токен его не видит | — |

План курса по умолчанию: 5% в день старта, 25% к концу недели 1, 50% — 2,
65% — 3, 90% — 4, 100% — к Demo Day.

Помните: процент — это какие файлы есть в репозитории. Это не оценка
человека. Говорите «в репозитории пока нет…», а не «вы не сделали».

## Плейбук вмешательств

### Флаг «нет доступа»

| Причина | Что сделать | Кто |
|---|---|---|
| опечатка в `repo` в `roster.csv` | исправить строку, перезапустить проверку | тренер |
| репозиторий закрытый, токен его не видит | участник добавляет вас в **Collaborators** с ролью Read, или репозиторий создаётся в организации курса | участник |
| репозитория ещё нет | созвон 20 мин: [00-novice.md](00-novice.md), шаг 5 | тренер |

### Флаг «застрял»

Сначала проверьте простое:

1. Работает в другой ветке? Посмотрите ветки на GitHub. Если да — впишите
   ветку в колонку `branch` или попросите слить работу в основную ветку.
2. Работает, но не делает push? Попросите `/airl-context закончить задачу`.

Если правда стоит — по этапу:

| Где застрял | Частая причина | Что предложить |
|---|---|---|
| Старт | нет репозитория или `CLAUDE.md` | созвон 20 мин, вместе пройти [00-novice.md](00-novice.md), шаги 5–7 |
| План | не может посчитать боль в цифрах | вместе запустить `/airl-spec`, раздел 1; предложить замер за неделю |
| Данные | боится базы; нет доступа к 1С или CRM | `/airl-modules` на демо-данных; `/airl-connect`; доступ — эскалация инженеру |
| Защита | «СРОЧНО» не закрыты | `/airl-cybersecurity` повторно — проверит только красное |
| Запуск | нет сервера, страшно выкладывать | `/airl-code-review`, затем `/airl-devops` по частям; сломалось — `/airl-debug` |
| Demo Day | хаб: сервис не принят | `/airl-hub самопроверка`, потом приёмка инженером |

### Флаг «отстаёт»

- Отставание до 25 пунктов: сообщение + офис-часы на этой неделе.
- Больше 25 пунктов или второй раз подряд: созвон 30 минут, урезать объём.
  Убрать экраны в «Не делаем сейчас» через `/airl-spec` (режим развития).
  Сообщить продакт-менеджеру, если это хаб и отдел может не успеть.

### Флаг «впереди»

- Похвалить публично на созвоне (с согласия).
- Предложить полезное дополнительное: `/airl-ai` (сводка в Telegram),
  режим P `/airl-spec` (полный PRD), помощь соседу по отделу.
- Не предлагать «ещё экранов» сверх `SPEC.md`.

### Участник пропал

- День 1–2 без ответа: повторное сообщение в личку.
- День 3: сообщение его руководителю (в хабе) или продакт-менеджеру.
- Неделя: решение с PM — продолжает с урезанным объёмом, передаёт модуль
  коллеге или выходит из потока.

## Как принимать этап

`/airl-progress` говорит, есть ли файлы. Вы проверяете, что внутри не пустота.
Приёмка — в пятницу, по чек-листу недели. Принято — напишите участнику
одной строкой. Не принято — один конкретный шаг.

| Этап | Что проверить глазами (5–10 мин) | Не принимать, если |
|---|---|---|
| Старт | `CLAUDE.md` описывает продукт, есть «Следующий шаг» | шаблон без замен |
| План | «Цена боли» — правдоподобная цифра, способ замера понятен; критерии проверяемы действием или числом; хаб: `id` в `airl.service.json` совпадает с отделом в карте | «Цена боли: много»; критерий «удобно» |
| Данные | главное действие работает — попросите показать экран или видео 30 сек; в хабе нет своих формул показателей | экраны на заглушках без плана перейти на данные |
| Защита | первая строка `SECURITY.md`: «да»; таблица «Проверки действием» заполнена | «СРОЧНО» в находках |
| Запуск | «Блокирующих замечаний: 0»; живой адрес открывается; откат выполнялся | `REVIEW.md` на старом коммите, а выложено новое |
| Demo Day | репетиция прошла; цифры «было → стало» есть | цифры придуманы без замера |

`REVIEW.md` может написать и тренер — по шаблону навыка, вместе
с участником, запустив `/airl-code-review`. В поле «Проверял» — навык и ваше
имя.

## Когда звать инженера

Эскалация (передача вопроса инженеру AIRL) — **в тот же день**, если:

- нет доступа к данным (тестовое хранилище, 1С, CRM) больше 1 рабочего дня;
- `/airl-debug` трижды не смог исправить ошибку;
- проблема на сервере хаба или общем сервере (502 у всех, сервер недоступен);
- нужно изменить права в хранилище, провайдер входа, тестовых пользователей;
- в `SECURITY.md` пункт «Для команды AIRL»;
- нужен вопрос к карте компании (новый показатель, отдел) — плюс владелец карты;
- подозрение на утечку ключа или персональных данных — **сразу**, не ждать.

Как передавать — одним сообщением в рабочий чат инженеров:

```
Кто: Данияр К., отдел продаж, компания X, репозиторий <ссылка>
Что: /airl-dwh не подключается к тестовому хранилищу, ошибка permission denied
Когда началось: вчера 15:00
Что пробовали: перепроверили .env, /airl-debug дважды
Что нужно: проверить права svc_sales
Срочность: блокирует неделю 2
```

Кто из инженеров что ведёт — в [03-engineer.md](03-engineer.md), раздел
«Распределение нагрузки».

## Группа из 10–30 человек

| Размер | Как вести |
|---|---|
| до 10 | один тренер, всё сам |
| 11–20 | один тренер + помощник (староста из сильных участников) на вопросы установки и git |
| 21–30 | два тренера, группа делится по компаниям или путям (solo/hub); одна общая сводка `/airl-progress` с фильтром «Компания» |

Приёмы:

- **Один список, несколько потоков.** Все участники в одном `roster.csv`,
  колонка `cohort`. Отчёт показывает общую статистику и сравнение потоков.
- **Монорепозиторий хаба.** Если отделы работают в одном репозитории,
  в колонке `path` укажите подпапку каждого сервиса — прогресс считается
  по ней.
- **Пары.** Новичку в пару — участника, который уже прошёл этап.
- **Типичные ошибки — на общий созвон.** Одна ошибка у трёх человек —
  разбор для всех, а не три личных созвона.
- **Чат группы**: правило «вопрос — скриншот — ссылка на репозиторий».
  Закреплённое сообщение с [шпаргалкой](00-novice.md#шпаргалка-на-одну-страницу).
- **Офис-часы по записи**, слоты по 15–20 минут. Без записи не принимать —
  иначе один участник съедает всё время.

## Метрики качества сопровождения

Смотрите в конце каждой недели. Пишите их в пятничный отчёт PM.

| Метрика | Где взять | Цель |
|---|---|---|
| Средний процент потока против плана | отчёт `/airl-progress`, плитки | не ниже плана больше чем на 10 пунктов |
| Доля «застрял» | отчёт, флаги | меньше 15% группы |
| Время реакции на флаг | ваш журнал | в тот же рабочий день |
| Время снятия блокера доступа | журнал эскалаций | меньше 2 рабочих дней |
| Этап «План» пройден к концу недели 1 | воронка этапов | 80% группы и больше |
| `SECURITY.md` «да» к концу недели 3 | тепловая карта, пункт `security_ok` | 70% и больше |
| Дошли до Demo Day с цифрой «было → стало» | репетиции | 80% и больше |
| Хаб: сервисы приняты к Demo Day | `/airl-hub готовность` | все отделы из `SCOPE.md` |
| Удовлетворённость | короткий опрос в конце недели 2 и после Demo Day | 8 из 10 и выше |
