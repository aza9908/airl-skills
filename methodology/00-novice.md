# С нуля, если вы никогда не программировали

Эта инструкция для тех, кто ни разу не писал код. Ничего страшного: на курсе
код пишет Claude, а вы отвечаете на его вопросы. Ваша задача — поставить
программы, создать место для проекта и научиться трём простым привычкам.

Займёт 1–2 часа один раз. Обычно это делают на офлайн-дне вместе с тренером.
Если что-то не получается — не мучайтесь дольше 15 минут. Сделайте скриншот
(снимок экрана) и напишите тренеру.

Каждый шаг устроен так: **что делаем → куда нажать → как проверить**.
Где Windows и macOS отличаются, шаги даны отдельно.

---

## Что понадобится

- Компьютер с Windows 10/11 или macOS. Лучше свой или с правами на установку
  программ. На корпоративном ноутбуке без прав администратора попросите ИТ-отдел
  поставить программы из шагов 2 и 3 заранее.
- Интернет.
- Почта, к которой у вас есть доступ.
- Аккаунт Claude с платной подпиской или доступ, который выдала компания
  или команда AIRL. Уточните у тренера, какой именно у вас.

## Шаг 1. Аккаунт на GitHub

**GitHub** (сайт, где хранятся проекты и вся история их изменений) — это ваш
сейф для проекта. Если компьютер сломается, проект останется на GitHub.

1. Откройте в браузере сайт `github.com`.
2. Нажмите **Sign up** (зарегистрироваться) в правом верхнем углу.
3. Введите почту, придумайте пароль и имя пользователя (латиницей, например
   `aliya-sales`). Имя увидят тренеры — пусть будет понятным.
4. Пройдите проверку «я не робот» и введите код из письма.
5. Включите двухфакторный вход (вход по паролю и коду из телефона):
   аватарка справа вверху → **Settings** → **Password and authentication** →
   **Enable two-factor authentication**. Следуйте подсказкам. Сохраните
   резервные коды в надёжном месте, не в чате.

**Как проверить:** вы вошли на `github.com` и видите свою аватарку справа вверху.

Напишите тренеру ваше имя пользователя на GitHub.

## Шаг 2. Git — программа, которая запоминает версии

**Git** (программа, которая сохраняет снимки вашего проекта, — как «история
версий» в Google Документах) нужен, чтобы ничего не терялось и любую ошибку
можно было откатить.

### Windows

1. Откройте сайт `git-scm.com` → **Download for Windows**.
2. Скачайте установщик **64-bit Git for Windows Setup**.
3. Запустите файл. На всех экранах нажимайте **Next**, ничего не меняя.
   В конце — **Install**, потом **Finish**.

На Windows Git обязателен: без него Claude Code не запустится.

### macOS

1. Откройте программу **Терминал**: нажмите **Cmd + Пробел**, наберите
   `Терминал` (или `Terminal`), нажмите Enter.
2. Вставьте команду и нажмите Enter:

   ```bash
   git --version
   ```

3. Если появилось окно «Установить инструменты разработчика» — нажмите
   **Установить** и дождитесь конца (5–15 минут).

**Как проверить (обе системы):** после установки VS Code (шаг 3) откройте в нём
терминал и наберите `git --version`. Должно появиться что-то вроде
`git version 2.47.0`. Номер может быть другим — это нормально.

## Шаг 3. VS Code — редактор, где вы будете работать

**VS Code** (бесплатная программа от Microsoft для работы с проектами) — ваше
рабочее место. В нём будет панель Claude, файлы проекта и терминал.

### Windows

1. Откройте `code.visualstudio.com` → **Download for Windows**.
2. Запустите скачанный файл. Примите соглашение.
3. На экране «Дополнительные задачи» поставьте галочки:
   **Добавить в PATH** и **Добавить действие «Открыть с помощью Code»**.
4. **Install** → **Finish**.

### macOS

1. Откройте `code.visualstudio.com` → **Download for Mac**.
2. Откройте скачанный архив. Перетащите **Visual Studio Code** в папку
   **Программы** (Applications).
3. Запустите VS Code из папки «Программы». На вопрос «Открыть программу из
   интернета?» нажмите **Открыть**.

**Как проверить:** VS Code открыт, слева узкая полоса со значками.

Полезно знать, где что:

| Что | Где | Сочетание клавиш |
|---|---|---|
| Файлы проекта | значок с листами слева (Explorer) | Ctrl + Shift + E · Cmd + Shift + E |
| Изменения и Git | значок с веткой слева (Source Control) | Ctrl + Shift + G · Cmd + Shift + G |
| Расширения | значок с квадратиками слева (Extensions) | Ctrl + Shift + X · Cmd + Shift + X |
| Терминал | меню **Terminal → New Terminal** | Ctrl + ` · Cmd + ` |
| Командная строка VS Code | — | Ctrl + Shift + P · Cmd + Shift + P |

**Терминал** (окно, куда вводят текстовые команды для компьютера) — это чёрное
или белое окно внизу VS Code. Команды из этой инструкции туда вставляются
целиком: скопировали → кликнули в терминал → вставили → Enter.

## Шаг 4. Расширение Claude Code и вход

**Расширение** (дополнение к программе) Claude Code добавляет в VS Code панель,
где вы разговариваете с Claude.

1. В VS Code нажмите значок **Extensions** слева (квадратики).
2. В поиске наберите `Claude Code`.
3. Выберите расширение от издателя **Anthropic** (проверьте имя издателя!).
   Нажмите **Install**.
4. Справа или слева появится значок Claude. Нажмите его.
5. Нажмите **Sign in** (войти). Откроется браузер. Войдите в свой аккаунт
   Claude и разрешите доступ. Вернитесь в VS Code.

**Как проверить:** в панели Claude напишите `Привет, ответь по-русски`.
Claude должен ответить.

Если Claude отвечает по-английски — напишите: «Отвечай на русском языке».

## Шаг 5. Папка проекта и репозиторий

**Репозиторий** (папка проекта вместе со всей историей изменений) будет
и у вас на компьютере, и на GitHub.

Есть два случая. Спросите тренера, какой у вас.

### Случай А. Свой продукт — создаём новый репозиторий

1. Создайте на компьютере пустую папку для проекта. Имя — латиницей, без
   пробелов, например `calls-tracker`.
   - Windows: Проводник → **Документы** → правый клик → **Создать → Папку**.
   - macOS: Finder → **Документы** → правый клик → **Новая папка**.
2. В VS Code: **File → Open Folder** (на Mac **File → Open…**) → выберите эту
   папку → **Открыть**. На вопрос «Доверяете ли вы авторам?» нажмите
   **Yes, I trust the authors**.
3. Создайте первый файл, чтобы было что сохранить: в панели файлов нажмите
   значок «новый файл», назовите `README.md`, напишите одну строку — название
   проекта. Сохраните: **Ctrl + S** (Mac: **Cmd + S**).
4. Откройте **Source Control** (значок с веткой слева).
5. Нажмите **Initialize Repository** (создать репозиторий).
6. В поле **Message** напишите `Начало проекта` и нажмите **Commit**.
   Если VS Code спросит «Нет подготовленных изменений, сохранить все?» —
   нажмите **Yes**.
7. Если появится ошибка «Make sure you configure your user.name and
   user.email», откройте терминал и введите (со своими данными):

   ```bash
   git config --global user.name "Алия Сапарова"
   git config --global user.email "почта@которую-указали-на-github"
   ```

   Потом снова нажмите **Commit**.
8. Нажмите **Publish Branch** (опубликовать ветку).
9. VS Code попросит войти в GitHub: **Allow** → в браузере **Authorize**.
10. Выберите **Publish to GitHub private repository** (закрытый репозиторий).
11. Дайте доступ тренеру: на `github.com` откройте репозиторий → **Settings** →
    **Collaborators** → **Add people** → имя тренера на GitHub → роль **Read**.
    Если курс идёт в организации AIRL на GitHub, тренер скажет, как сделать
    иначе.

**Как проверить:** на `github.com` в вашем профиле есть новый репозиторий,
в нём файл `README.md`. Отправьте ссылку тренеру.

### Случай Б. Хаб компании — репозиторий уже создан командой AIRL

Команда AIRL готовит для каждого отдела репозиторий из шаблона. Вам пришлют
ссылку и приглашение.

1. Примите приглашение: письмо от GitHub → **View invitation** → **Accept**.
2. В VS Code: командная строка (**Ctrl + Shift + P**, на Mac **Cmd + Shift + P**)
   → наберите `Git: Clone` → Enter.
3. Вставьте ссылку на репозиторий → Enter.
4. Выберите, куда положить (например, «Документы») → **Select as Repository
   Destination**.
5. На вопрос «Открыть клонированный репозиторий?» нажмите **Open**.

**Как проверить:** в панели файлов видны файлы шаблона, например `Dockerfile`.

## Шаг 6. Установка навыков AIRL

**Навык** (готовая подробная инструкция для Claude) ведёт вас по курсу
вопросами. Навыки AIRL ставятся одним плагином (пакетом навыков).

1. Откройте терминал: **Terminal → New Terminal**.
2. Вставьте первую команду и нажмите Enter:

   ```bash
   claude plugin marketplace add aza9908/airl-skills
   ```

3. Вставьте вторую команду и нажмите Enter:

   ```bash
   claude plugin install airl@airl-skills
   ```

   Должно появиться `Successfully installed plugin: airl@airl-skills`.
4. Перезагрузите окно: **Ctrl + Shift + P** (Mac: **Cmd + Shift + P**) →
   наберите `Developer: Reload Window` → Enter.

Если терминал пишет `command not found: claude` или «не является внутренней
или внешней командой» — сделайте то же самое в панели Claude:
наберите `/plugins` → вкладка **Marketplaces** → добавьте `aza9908/airl-skills`
→ вкладка **Plugins** → установите `airl`. Потом перезагрузите окно.

**Как проверить:** в панели Claude наберите `/airl`. Под полем появится список
навыков на русском, например `/airl:airl-spec`.

Команды набираются в **панели Claude**, а не в терминале.

## Шаг 7. Первый запуск: память проекта

**`CLAUDE.md`** (короткий файл-памятка о проекте) Claude читает в начале
каждого чата. Благодаря ему не нужно каждый раз объяснять всё заново.

1. В панели Claude наберите:

   ```
   /airl:airl-context начать проект
   ```

2. Claude посмотрит папку, задаст вопросы и создаст `CLAUDE.md`.
3. Когда он предложит закоммитить и отправить на GitHub — ответьте «да».

**Как проверить:** в панели файлов появился `CLAUDE.md`. На GitHub он тоже есть.

## Шаг 8. Первый запуск /airl-spec — техническое задание

**ТЗ** (техническое задание — описание, что строим и зачем) пишет навык
`/airl-spec`. Начните **новый чат** (как — в разделе «Ежедневный ритуал»)
и наберите:

```
/airl:airl-spec учёт звонков клиентам для отдела продаж
```

Вместо «учёт звонков…» напишите свою задачу одной фразой. В хабе компании
напишите: `/airl:airl-spec ТЗ отдела продаж` (название своего отдела).

Навык всегда начинает с двух вопросов:

1. **Как вас зовут и кем вы работаете** — напишите имя и букву, например
   `Алия, C`.
2. **Из какого вы отдела** — одна буква, например `D`.

Дальше навык спрашивает о боли: что сейчас отнимает время и сколько.

В конце появятся `SPEC.md` и `ARCHITECTURE.md` (схема продукта). В хабе ещё
`airl.service.json` и копия карты `airl/COMPANY_MAP.md`.

## Как отвечать на вопросы навыка

Навык задаёт **один вопрос за раз**. К вопросу — 2–4 варианта с буквами
и рекомендация.

```
Вопрос 5 из 11. Где сейчас больнее всего?

A) Отчёт руководителю собирается руками из 1С и CRM — рекомендую
B) Заявки теряются между рекламой и менеджером
C) Свой вариант
```

Правила:

- **Можно ответить одной буквой**: `A`.
- **Не знаете — так и напишите**: «не знаю». Навык возьмёт рекомендацию
  и скажет об этом.
- **Свой вариант** — пишите обычными словами, как коллеге.
- **Давайте цифры**, даже примерные: «примерно 5 часов в неделю», «около
  20 заявок в день». Цифры нужны для Demo Day.
- **Не понимаете слово — спросите**: «что такое витрина?». Навык объяснит
  на примере и вернётся к вопросу.
- **Ошиблись — поправьте**: «в вопросе 3 я ошибся, правильно B».
- Перед важным действием (удаление, выкладка, запись в базу) навык спросит
  «да?». Отвечайте «да», только если понимаете, что произойдёт. Не уверены —
  «объясни, что будет».

## Ежедневный ритуал: новая задача — новый чат

Claude перечитывает **всю** историю чата перед каждым ответом. Длинный чат
быстро съедает лимит (дневной запас работы Claude). Поэтому:

**Одна задача — один новый чат.**

### В начале задачи

1. Откройте **новый чат**: значок «+» или **New chat** вверху панели Claude.
   Если не нашли — наберите в панели `/clear`.
2. Напишите:

   ```
   /airl:airl-context начать задачу: собрать главный экран
   ```

3. Claude прочитает `CLAUDE.md`, создаст **ветку** (отдельную копию проекта
   для этой задачи, чтобы не сломать основную) и скажет план.

### В конце задачи

1. Напишите:

   ```
   /airl:airl-context закончить задачу
   ```

2. Claude проверит работу, сохранит изменения, обновит `CLAUDE.md`
   и отправит всё на GitHub. На вопрос про основную ветку отвечайте «да»,
   если задача готова и проверена.
3. Следующую задачу — снова в новом чате.

Следующий навык курса (например, `/airl-dwh` после `/airl-spec`) — тоже
в новом чате. Ничего не потеряется: всё записано в файлах проекта.

Ещё три команды в панели Claude:

| Команда | Что делает | Когда |
|---|---|---|
| `/compact` | сжимает историю чата в краткую выжимку | чат стал длинным, а задача не закончена |
| `/clear` | очищает чат полностью | задача закончена и `CLAUDE.md` обновлён |
| `/context` | показывает, чем занят чат | интересно, почему тратится лимит |

## Как сохранить работу: commit и push простыми словами

- **Commit** (коммит) — снимок проекта с подписью «что сделал». Как кнопка
  «Сохранить версию». Снимок остаётся у вас на компьютере.
- **Push** (пуш) — отправка снимков на GitHub. Как «синхронизировать
  с облаком». Только после push тренер видит вашу работу, а
  `/airl-progress` считает прогресс.

Обычно всё делает Claude по команде `/airl:airl-context закончить задачу`.
Если нужно сделать руками:

1. Откройте **Source Control** (значок с веткой).
2. Посмотрите список изменённых файлов. Если среди них есть `.env` —
   **остановитесь** и напишите тренеру: этот файл с ключами нельзя отправлять.
3. В поле **Message** коротко опишите: `Добавил главный экран`.
4. Нажмите **Commit**.
5. Нажмите **Sync Changes** (или **Publish Branch** для новой ветки).

**Как проверить:** на `github.com` в репозитории видно ваше сообщение
и время «несколько минут назад».

Правило: **отправляйте работу на GitHub хотя бы раз в день**, когда работали.
Если 4 дня нет отправок, `/airl-progress` пометит «застрял», и тренер
напишет вам.

## Если появилась ошибка

1. **Не паникуйте и ничего не удаляйте.** Почти любую ошибку можно исправить,
   если работа сохранена в git.
2. **Новый чат** и команда:

   ```
   /airl:airl-debug
   ```

   Опишите: что делали, что ожидали, что увидели. Приложите **скриншот
   целиком**:
   - Windows: **Win + Shift + S**, выделить область, вставить в чат
     **Ctrl + V**;
   - macOS: **Cmd + Shift + 4**, выделить область; файл появится на рабочем
     столе, перетащите его в чат.
3. Если ошибка в браузере (белый экран, не грузится): нажмите **F12**
   (Mac: **Cmd + Option + I**) → вкладка **Console** → скриншот красных строк.
4. Если `/airl-debug` три раза не смог исправить — он сам скажет позвать
   инженера. Напишите тренеру в чат группы:
   - что делали и что сломалось (одна-две фразы);
   - скриншот;
   - ссылка на репозиторий;
   - что уже пробовали.
5. Тренер ответит или передаст инженеру AIRL.

Длинный текст ошибки не вставляйте целиком — только последние 30–50 строк.

## Чего никогда не делать

| Нельзя | Почему | Как правильно |
|---|---|---|
| Вставлять в чат пароли, ключи, токены (длинные строки-пароли для программ) | всё, что в чате, видит модель; ключ может утечь | ключи только в файл `.env`, навык подскажет как |
| Отправлять на GitHub файл `.env` | его могут прочитать другие | `.env` должен быть в `.gitignore`; навыки это проверяют |
| Удалять файлы и папки без копии | восстановить будет нечем | сначала commit и push, потом удаляйте |
| Вставлять в чат настоящие данные клиентов (ФИО, телефоны, ИИН) | это персональные данные, по закону их нельзя раздавать | работайте с тестовыми или обезличенными данными |
| Отвечать «да» на действие, которое не понимаете | можно сломать сервер или базу | спросите «что будет, если да?» |
| Вводить на сервере команды из интернета | опасные команды удаляют данные | только по памятке `DEVOPS.md` и с навыком `/airl-devops` |
| Работать неделю в одном чате | лимит кончится за день, Claude начнёт путаться | одна задача — один чат |
| Делиться своим аккаунтом Claude или GitHub | вас не смогут отличить от другого человека | у каждого свой аккаунт |

## Частые вопросы новичков

**1. Мне правда не нужно уметь программировать?**
Нет. Вы отвечаете на вопросы о своей работе, а код пишет Claude. Нужно уметь
нажимать кнопки по инструкции и честно отвечать.

**2. Сколько времени это займёт в неделю?**
4–6 часов: около 3 часов — урок и упражнения, остальное — работа над
продуктом с навыками.

**3. Я написал `/airl-spec`, а ничего не происходит.**
Проверьте, что пишете в панели Claude, а не в терминале. При установке
плагином команда полная: `/airl:airl-spec`. Начните набирать `/airl` —
появится список.

**4. Чем панель Claude отличается от терминала?**
Панель Claude — разговор с Claude обычными словами. Терминал — окно для
коротких команд компьютеру. Навыки запускаются в панели.

**5. Claude пишет «лимит исчерпан». Что делать?**
Подождите, пока лимит обновится (время Claude напишет). Чтобы это случалось
реже: одна задача — один чат, не вставляйте длинные тексты, используйте
`/compact`. Подробнее — `/airl:airl-context экономия`.

**6. Я закрыл VS Code. Работа пропала?**
Нет. Файлы на компьютере. Если вы сделали commit и push — они ещё и на
GitHub. Откройте папку снова: **File → Open Recent**.

**7. Claude «всё забыл» в новом чате.**
Так и задумано. Он помнит через `CLAUDE.md`. Начните с
`/airl:airl-context начать задачу: …` — он прочитает памятку.

**8. Что такое ветка и зачем она?**
Ветка — отдельная копия проекта для одной задачи. Если что-то пойдёт не так,
основная версия не пострадает. Ветки создаёт и сливает Claude.

**9. Можно ли работать с двух компьютеров?**
Да. На втором компьютере клонируйте репозиторий (шаг 5, случай Б). Перед
работой нажимайте **Sync Changes**, после — commit и push.

**10. Навык спросил то, чего я не знаю.**
Напишите «не знаю». Навык возьмёт рекомендацию и запишет её в раздел «Решено
по умолчанию». Потом это можно поменять.

**11. Я не знаю, сколько часов уходит на мою задачу.**
Навык предложит, как замерить за неделю. Например: каждый день записывать
в заметку, сколько минут ушло на отчёт. Это и будет «было» для Demo Day.

**12. Можно ли писать на казахском или узбекском?**
Да. Навык ответит на вашем языке. Документы пишутся на языке, который
выбрала компания.

**13. Claude предлагает что-то установить или выполнить команду. Соглашаться?**
Если это шаг навыка и вы понимаете зачем — да. Если непонятно — спросите
«зачем это и что будет?». Команды, которые что-то удаляют, без копии
не выполняйте.

**14. Тренер пишет, что я «застрял». Это плохо?**
Это не оценка. Это значит, что 4 дня нет новых файлов на GitHub. Возможно,
вы работаете, но не отправили работу. Сделайте push или напишите тренеру,
что мешает.

**15. Где взять доступ к 1С, CRM или серверу?**
Не у Claude. В хабе компании доступы выдаёт команда AIRL. В своём продукте —
администратор вашей системы. Навык подскажет, что именно попросить.

**16. Я случайно вставил пароль в чат. Что делать?**
Сразу скажите тренеру. Пароль нужно сменить там, где он используется.
Это не катастрофа, если сделать быстро.

**17. Почему у меня Windows пишет «git не является командой»?**
Git не установлен или VS Code открыт до установки. Поставьте Git (шаг 2),
закройте и снова откройте VS Code.

**18. Можно ли пользоваться ChatGPT вместо Claude?**
Навыки курса работают в Claude Code. В других программах их нет.

**19. Что показывать на Demo Day?**
Боль и её цену «было», живой продукт и цифру «стало». Подробно —
[01-participant.md](01-participant.md), раздел Demo Day.

## Шпаргалка на одну страницу

**Один раз**

1. Аккаунт на `github.com` с двухфакторным входом.
2. Git: Windows — `git-scm.com`; macOS — `git --version` в Терминале.
3. VS Code: `code.visualstudio.com`.
4. Расширение **Claude Code** (издатель Anthropic) → **Sign in**.
5. Папка проекта → **Source Control** → **Initialize Repository** →
   **Commit** → **Publish Branch** (private). Хаб: **Git: Clone** по ссылке.
6. Навыки в терминале:
   `claude plugin marketplace add aza9908/airl-skills`
   `claude plugin install airl@airl-skills`
   → **Developer: Reload Window**.
7. В панели Claude: `/airl:airl-context начать проект`.

**Каждая задача**

| Когда | Что набрать в панели Claude |
|---|---|
| начало (в новом чате) | `/airl:airl-context начать задачу: <что>` |
| конец | `/airl:airl-context закончить задачу` |
| ошибка | `/airl:airl-debug` + скриншот |
| чат длинный | `/compact` |

**Порядок навыков**

`/airl-spec` → `/airl-modules` → `/airl-dwh` → `/airl-pwa` →
`/airl-cybersecurity` → `/airl-code-review` → `/airl-devops` →
(`/airl-ai`) → хаб: `/airl-hub самопроверка`.
Каждый — в новом чате.

**Нельзя**: ключи в чат · `.env` на GitHub · удалять без копии ·
«да» на непонятное · настоящие ФИО и телефоны в чат.

**Помощь**: тренер в чате группы — что делали, скриншот, ссылка
на репозиторий, что пробовали.
